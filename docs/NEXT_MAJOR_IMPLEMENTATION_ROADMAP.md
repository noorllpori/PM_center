# Nexora 实施路线与验收状态

> 当前基线：Nexora 2.8.5
>
> 更新日期：2026-08-12

本文件只记录当前路线。R0-R14 的具体设计、实施步骤和旧验收证据在 [历史归档](archive/2026-08-12/README.md) 中保留。

## 状态含义

- pending：范围已冻结，未开始。
- in progress：正在开发，不是稳定外部合同。
- verifying：代码与自动检查已完成，等待人工或实机验收。
- accepted：已验收，可作为后续稳定依赖。

## 固定依赖

1. R15 必须复用本地组件签名、信任、依赖、安装和回退，不建立第二套包格式。
2. R16 使用 R15 的账户和设备身份，但不上传组件二进制、项目、媒体、聊天、密钥或绝对路径。
3. 长期稳定的 R17 ABI 需要 R14 发布基线与 R15 可控更新渠道；当前界面模板子路线不等于完整 R17。
4. R18 的节点编排只组合 R11 自动化和完整 R17 ABI，旧 Workflow 合同继续冻结。

## 当前优先顺序

1. 完成 R17/R18 界面模板子路线的人工验收和编辑器收口。
2. 完成 R12-R14 的真实环境、双机、安装和回滚验证。
3. 在 R14 达到发布门槛后，按 R15、R16、完整 R17、完整 R18 的顺序进入正式开发。

## 通用验收门槛

每个里程碑必须具备稳定接口、幂等迁移、明确错误、取消与恢复语义、资源释放、文档同步和回滚路径。至少运行 TypeScript、Vite、Rust、Schema/合同检查、相关样例、git diff --check，并完成对应的人工或实机验收。

R15-R18 的完整范围见 [云端生态与宿主扩展路线](NEXT_MAJOR_R15_R18_CLOUD_ECOSYSTEM_AND_HOST_ABI.md)，当前模板专项见 [R17-R18 界面模板与插槽装配](NEXT_MAJOR_R17_R18_INTERFACE_TEMPLATE_SLOTS.md)。
