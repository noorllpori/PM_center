# Nexora Server 混合协作架构

## 通道

- `lan`：UDP 31523 广播发现，TCP 31524 单路消息与文件直传，不依赖服务器。
- `server`：客户端连接 `/api/v1/ws`，用于跨网络在线状态、私聊、服务器大厅和文件控制。
- 联系人使用稳定 `deviceId` 合并。文字自动模式优先 LAN，LAN 失败时可尝试 Server；文件发送前固定通道。

## 身份与存储

- 服务端没有用户账号。首次登记为 `deviceId` 签发随机设备凭据，凭据哈希写入服务端 SQLite。
- 客户端共享密码与设备凭据存系统凭据库；地址、开关、服务端 ID 写入客户端 SQLite。
- 设备资料与头像持久化。服务器大厅及每对设备私聊各保留最近 30 条。

## 文件中转

1. 发送方通过 WebSocket 报价，接收方接受或拒绝。
2. 接收方先打开带随机令牌的 GET 下载流。
3. 服务端确认 GET 就绪后才向发送方下发 PUT 上传地址。
4. 服务端通过 1 MiB `tokio::io::duplex` 有界缓冲转发，并把实际转发字节推送给双方。
5. 客户端沿用清单、BLAKE3、临时 `.part`、图片解码校验及原子提交。服务端不落盘。

任一端断开或取消后会删除内存会话并关闭流。首版不支持离线文件、断点续传或失败后自动换通道。

## 部署

默认监听 `0.0.0.0:7412`。可信网络可直接使用 HTTP；公网使用 `server/deploy/Caddyfile.example` 提供 HTTPS/WSS。
