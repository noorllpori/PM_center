# 局域网传输与同步架构

## 目标

局域网聊天附件、目录传输、项目同步和远端资源拉取共用一个传输内核。业务功能只负责生成清单、展示差异和决定写入策略，不再各自建立 TCP 服务、进度事件或临时文件机制。

当前版本只启用私聊单文件传输。一次选择多个文件会生成多个独立任务，单个失败不会阻塞其他文件。

本机接收根目录属于 `lan_local_settings`，不得写入广播资料或项目数据库。文件适配器在根目录下按发送者名称建立安全子目录并预留不覆盖的目标路径；小于等于 100 MB 的有效图片可自动领取，其他 payload 仍必须显式确认。

## 固定分层

1. `transport`：连接、超时、限速、分块读写和进度，不理解项目与目录。
2. `transfer engine`：`offer -> accept/reject -> request -> stream -> verify -> receipt` 状态机、任务持久化、恢复与取消。
3. `payload adapter`：按 `kind + payloadFormat + manifest.version` 生成和消费内容。
4. `sync planner`：比较本地与远端清单，生成新增、更新、冲突、跳过和删除候选项。
5. `feature surface`：聊天附件、目录发送或项目同步页面，只调用统一任务接口。

后续扩展只能增加 payload adapter 和 planner，不新增平行端口或另一套传输任务表。

## 稳定传输描述

每个任务必须包含：

- `kind`：业务类型，例如 `file`、`directory-snapshot`、`project-sync`。
- `payloadFormat`：线上的字节组织方式，当前为 `raw`，后续可增加 `archive-v1` 或 `chunk-stream-v1`。
- `manifest.version`：该业务清单的独立版本，不能用应用版本代替。
- `itemCount`、`totalBytes`：接收确认前可见的规模信息。
- 内容哈希：当前单文件使用 BLAKE3；多项任务应同时有每项哈希和整份清单哈希。

manifest 不得包含发送方绝对路径、账号目录或其他机器隐私信息。清单中的路径必须是 UTF-8 相对路径，统一使用 `/`，拒绝绝对路径、`..`、空段、Windows 保留名和大小写冲突。

## 目录传输

目录传输使用 `directory-snapshot`，先扫描得到不可变清单，再发出请求。接收方在确认界面查看文件数、总大小、目标目录、重名数量和危险项。

第一阶段采用完整快照：

- 默认不跟随符号链接或目录联接点。
- 默认忽略 `.pm_center`、临时文件和调用方给出的排除规则。
- 每项记录相对路径、类型、大小、修改时间和 BLAKE3。
- 接收端先写任务级暂存目录，全部校验通过后再逐项提交。
- 覆盖、保留两份和跳过必须由用户在开始传输前选择。
- 删除目标目录中多余文件永远是单独动作，不能由“接收目录”隐式执行。

大目录后续切换到 `chunk-stream-v1` 时，状态机和 UI 不变，只替换 payload adapter。

## 项目同步

项目同步不是“直接发送整个目录”，而是四步流程：

1. 双方交换项目标识、根清单哈希和能力版本，不交换文件内容。
2. 分页交换清单并在本机生成差异计划。
3. 用户确认同步方向、冲突策略、排除规则和预计传输量。
4. 将缺失内容转换为普通传输任务，校验后原子提交并重新扫描项目。

`.pm_center` 默认永不跨机器覆盖。以后若同步项目元数据，必须按数据库/API 语义单独设计迁移，不能当普通目录复制。脚本、插件、渲染输出和缓存分别设置显式开关，默认排除缓存和临时输出。

源和目标都变化的路径标为冲突，不按修改时间自动覆盖。首版只提供保留本机、使用远端、保留两份三种确认结果，不做静默双向合并。

## 恢复与一致性

- 用户确认前只持久化 offer 和 manifest，不发送正文。
- 领取任务必须通过数据库条件更新，多个窗口只能有一个成功。
- 数据写入同目录 `.part` 或任务暂存区，BLAKE3 校验通过后原子替换。
- 应用退出后 `preparing/transferring` 进入可重试失败态，不把部分文件当成完成。
- 重试复用原任务标识与清单；源内容变化时拒绝继续并要求重新创建 offer。
- receipt 丢失时双方状态可能暂时不一致；后续恢复协议应通过任务 ID 和内容哈希查询结果，不能直接重传覆盖。

## 安全与资源限制

- 连接身份至少同时校验联系人 ID 和当前发现到的 IP；未来可信设备功能应增加配对密钥和签名。
- 所有接收操作由本机用户选择目标位置，不接受发送方指定的绝对目标路径。
- 对 manifest 大小、单项数量、总字节、并行连接和磁盘剩余空间设上限。
- 传输内容目前为局域网明文。涉及项目同步前应增加可选加密与设备配对，不能把“已发现联系人”等同于可信设备。
- 文件内容、目录清单和项目差异都保存在软件级数据目录，不写入任意项目的 `.pm_center`，除非项目功能明确完成提交。

## 建议实施顺序

1. 当前：私聊文件、系统文件选择、拖拽、剪贴板图片、确认接收、哈希校验。
2. 文件集合：一个 offer 包含多项，提供整体接收和逐项结果。
3. 目录快照：安全相对路径、任务级暂存、冲突预检和空间检查。
4. 单向项目拉取：清单比较，只拉缺失或已确认更新的资源。
5. 双向项目同步：基线快照、冲突中心、审计记录和回滚清单。
6. 可信设备：配对、加密、权限范围、带宽和并发策略。

每一步都需要协议兼容测试、断线/重启恢复测试、路径穿越测试、同名大小写测试、大文件测试和双机真实联调。
