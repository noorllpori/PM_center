# R12：参考装配纵向验收

状态：`in progress`。2026-08-07 已完成本机自动化自验收；真实媒体、真实 Blender、双机和安装环境仍是未关闭的外部验收项，详见 `docs/NEXT_MAJOR_R12_R13_R14_ACCEPTANCE_AUDIT.md`。R12 不新增“项目管理器模式、聊天模式、媒体模式、渲染模式”之类的固定产品分支。每一种成品都必须是同一套 Profile、模块、组件、Contribution Registry 和组件包机制的可导入装配。

## R12-0 已实现：参考装配合同

`src-tauri/src/platform/reference_assemblies.rs` 定义参考装配的版本化最小合同，并在 Rust 测试中验证。

- 参考装配不会在用户机器上自动创建、自动启用或自动切换；它不改变当前 Profile。
- 合同先执行现有 `validate_profile_with_catalogs`，再检查主页、必需模块、页面、Widget、数据源、命令以及每一个被引用贡献的归属。
- 贡献只能来自当前启用模块或其有效组件。停用模块遗留的工具、页面或命令会被判为无效，不能形成半失效装配。
- `reference.*` 仅是夹具/合同标识。自动测试扫描 Rust 源文件，禁止用参考装配 ID 写 `if`/`match` 运行时分支。

这层只为后续四套参考成品提供同一种验收方式，不是用户可见的模式选择器。

## R12-A 已实现：项目管理器基线

第一份规范是 `reference.project-manager`，它表示最小可用的项目管理器装配：

- 启用 `builtin.project-manager` 以及其模块依赖 `builtin.project-resources`。
- 主页为项目主页贡献，包含项目目录、快速动作、最近项目、项目目录卡片。
- 页面依赖的四个数据源，以及新建、导入、打开项目三个命令完整存在。
- 局域网协同、渲染中心、智能剪贴板、自动化和文件处理器均不是该基线的隐式要求；需要时作为正常模块/组件叠加。

`build_project_manager_reference_profile` 会由实际模块清单递归计算必需模块版本，不把版本号写死。现有默认装配也有一条回归测试，确保它继续满足这份项目管理器合同。

## 当前自动验收

- 最小项目管理器 Profile 通过模块、组件和贡献归属校验。
- 默认 Profile 保留项目管理器参考合同。
- 向 Profile 强行插入一个未启用模块的固定工具会被拒绝。
- 源码中不存在按 `reference.project-manager` 选择运行时模式的分支。

## Shell 页面入口规则

“启动主页”只是 Nexora 启动后最先激活的页面，不是页面唯一入口。任何独立 Shell 页面都必须同时提供以下两种可选入口：

- **导航项**：在“界面装配 > 已加入导航”中勾选后，可随时打开同一个单例标签；
- **可固定工具**：在功能中心或“快捷栏”中加入后，可从顶部工具栏打开同一个单例标签。

因此，外部 Blender 渲染器、媒体资料库和设备协作都可以设为启动主页，也可以加入导航、固定到快捷栏，三种选择可同时存在且不创建重复页面。贡献目录会诊断缺少可固定工具入口的独立 Shell 页面，防止后续再出现“只能设为主页、没有其他入口”的页面。

## R12-C 已实现：局域网通信端基线

`reference.lan-communications` 使用同一 Profile schema，但只选择 `builtin.lan-collaboration`：

- 默认主页是已有的局域网主面板 Surface，不复制联系人、聊天或传输实现。
- Profile 不会选择项目管理器或项目资源模块；合同将这两个模块列为禁止项。
- 局域网模块清单被抽成可直接校验的纯清单。它不依赖项目模块，后台服务仅包含 UDP 发现、TCP 消息、服务器客户端和传输协调器。
- 自动测试验证这份最小 Profile、禁止模块以及后台服务目录；因此未来修改模块依赖时会立即发现“通信端偷偷拉起项目数据库/watcher”的设计回退。

这不是“双机联调已完成”的声明。真实设备发现、私聊、文件/目录传输、取消和 Windows 防火墙表现将在 R12-E 的两机验收中完成。

## R12-D 已实现：Blender 外部渲染器基线

`reference.external-blender-renderer` 只选择渲染中心、其外部工具依赖和 BlendIO 组件，不选择项目管理器或项目资源模块：

- 新增 Shell Surface `builtin.render-center.external-station-surface`。它复用同一份渲染中心界面，但不是项目工作区标签，也不会调用 `ProjectStore.setProject`。
- 首次打开时，后端只在应用数据目录创建 `render-station/`：队列数据库和 Worker 日志位于 `render-station/.pm_center/`，默认交付目录为 `render-station/renders/`。这只是现有调度器的私有队列命名空间，不是用户项目，也不会启动项目数据库注册、TreeCache 或文件 watcher。
- 外部渲染器的新建批次始终使用系统文件选择器选择 `.blend`、输出目录和 Python Hook；任何路径的源文件都可加入，不需要先导入项目。
- 渲染中心保留 `builtin.external-tools` 与 `pmc.blendio` 的真实依赖；`builtin.project-resources` 已从渲染中心的必需模块移除，因为 Worker、队列、原子交付和日志本来就由渲染中心自己的 SQLite 命名空间负责。
- 自动测试校验外部渲染器 Profile 的依赖闭包、禁止模块、Surface 归属、私有存储路径及创建后的渲染 schema。测试还确认应用数据根不会被写成项目 `.pm_center`。

这仍不是对真实 Blender 的性能或插件兼容性背书。R12-E 会在安装环境中执行真实 `.blend`、至少十帧、Worker 日志和输出预览的端到端验收。

## R12-B 已实现：媒体资料库基线

`reference.media-library` 只启用可停用的 `builtin.media-library`，页面和资料数据不依赖项目管理器、项目资源、目录 watcher 或项目 `data.db`：

- 用户选择任意普通目录作为资料库，资料库只会创建 `.pm_center/media_catalog.db` 和可选的 `media/` 归档目录。应用数据目录仅保存最近打开的资料库列表。
- 独立 SQLite schema 保存媒体条目、实际位置、BLAKE3、集合、标签、注释、评分、归档事件和派生资源预留表，并启用 WAL、外键和分页/位置/哈希索引。
- 支持“仅引用、复制入库、移动归档”。复制先写临时文件再原子提交；移动在提交副本和目录记录后才删除原文件。发现同内容时只关联新位置，绝不因为选择“移动”而删除重复来源。
- 支持选择文件或目录递归收集，当前包含图片、视频、音频及常用参考文件；页面提供网格浏览、图片/视频直接预览、集合、标签、备注和五星评分。
- 自动测试创建 10,000 条资料索引并验证搜索分页，也验证资料库数据库没有误写为项目 `data.db`，以及重复内容不会移动或删除来源。

视频封面、序列帧聚合、代理文件、OCR/相似度等属于后续可安装组件贡献；当前资料库保留 `media_derived_assets` 边界，不把这些实现绑定为不可替换的内核功能。

媒体资料库保持独立，才能作为无项目装配的主页、导航页或快捷工具使用。后续项目级媒体索引、项目资源关联和 `.pm_center` 元数据将由可选的“项目媒体桥接”组件提供；它依赖媒体资料库与项目资源，但不会反向让基础资料库强制启动项目 watcher 或项目数据库。
