# R7-3 设置中心贡献化与动态装配

更新时间：2026-08-05

## 1. 目标

设置页面不再是一组永远存在的硬编码表单。模块和组件通过稳定的 `settingsSections` 贡献声明自己的设置入口，设置中心只装配当前运行 Profile 中可用的贡献。

用户停用模块后，模块拥有的设置导航、设置内容和项目设置范围必须立即撤下；重新启用后使用原有持久化数据恢复，不执行任务、不清空配置，也不留下空白页面。

## 2. 两层设置架构

### 2.1 `core.recovery-settings`

恢复内核不可停用，只保留软件重新可用所必需的最小操作：

- 查看模块、组件和依赖错误；
- 启用或修复模块与组件；
- 切换 Profile；
- 恢复默认装配；
- 退出程序。

恢复内核不承载 Blender、插件、排除规则、历史记录等普通业务设置，也不接受第三方任意 React、脚本或未经净化的 HTML 注入。后续受控 Shell/Page 模板只改变表现层，不进入恢复设置内核。

### 2.2 `builtin.settings-center`

普通设置中心负责设置工具入口、弹窗或页面外壳、范围切换、导航、搜索和设置区宿主。它默认启用，最终可以像普通模块一样被 Profile 停用。

独立恢复入口现已落地，因此 `builtin.settings-center` 可以像普通模块一样停用。主标签栏和最小安全主页始终保留 `core.recovery-settings` 入口，避免用户失去恢复路径。

## 3. 设置贡献合同

每个设置贡献至少声明：

- 稳定贡献 ID；
- 所属模块或组件；
- `global` 或 `project` 范围；
- 导航 ID、标题、图标键和排序；
- 可用性策略；
- 受信任的 renderer ID。

普通可安装组件优先使用 schema 设置：布尔值、数字、字符串、路径、枚举、列表和分组由宿主统一渲染。只有随宿主登记的受信内置实现可以使用 renderer ID，组件包不能在主进程中直接注入 React、未经净化的 HTML 或脚本；受控 `base.html` 必须经过独立模板包合同和净化渲染器。

设置贡献只描述 UI 和设置数据入口，不拥有绕过 Capability Gateway 的权限。保存、检测、打开目录、重启服务等动作仍需经过模块生命周期和能力检查。

## 4. 当前迁移所有权

| 设置区域 | 目标所有者 | 本轮状态 |
| --- | --- | --- |
| 启动恢复、标签关闭确认 | `builtin.session-runtime` | 已拆分 |
| 开机自动启动 | `builtin.desktop-integration` | 已拆分 |
| 全局排除规则、项目规则 | `builtin.project-resources` | 已接入 |
| Python、任务脚本、全局/项目插件 | `builtin.automation-runtime` | 已接入 |
| Blender、FFmpeg、FFprobe、Blend 解析器 | `builtin.external-tools` | 已拆分 |
| 最近项目、忽略项目 | `builtin.project-manager` | 已接入 |
| 本机网页控制台 | `builtin.local-web-console` | 已接入 |
| Module/Profile/Capability 诊断、默认装配恢复 | `core.recovery-settings` | 已迁出普通设置中心 |
| Schema 设置宿主、关于 | `builtin.settings-center` | 已收敛为宿主能力 |
| 退出程序 | `core.recovery-settings` / `builtin.settings-center` | 两个入口均保留 |

内置业务设置继续使用受信 renderer，组件包可通过 Schema 声明设置字段并由宿主统一渲染。后续迁移新设置只需要明确所有者并选择 renderer 或 Schema，不再修改设置中心装配机制。

## 5. 运行时行为

- 设置中心从当前 Contribution Registry 计算可用贡献，不维护另一份模块开关表；
- 范围选择只显示至少存在一个可用贡献的范围，项目范围还要求当前项目已打开；
- 范围是一级菜单、设置贡献是二级菜单；右侧只挂载当前选中的设置页，不再通过长页面滚动定位其他设置区；
- 当前贡献被撤下时，选择同范围中最近的可用项；同范围为空时切换到另一个可用范围；
- 任何状态变化都不能留下空导航、空白正文或失效的 `<select>` 值；
- 模块停用后清理该设置区的临时草稿、异步请求结果和进行中 UI 状态，但不删除磁盘数据；
- 模块重新启用后重新读取持久化设置；
- 多个贡献可按排序组成同一范围，但稳定导航 ID 不允许冲突。

## 6. 停用确认约束

模块停用必须严格分成两个阶段：

1. 只调用 preview，读取依赖、活动资源和影响范围；
2. 显示应用内确认框，用户确认后才调用 disable。

取消必须是零副作用。不能使用先执行后弹框的系统确认，也不能因为预览失败而默认继续。涉及未保存设置时同样先提示，再执行关闭或切换。

## 7. 分阶段实施

### R7-3A：目录与动态装配

状态：已验收（2026-08-05）。

- 扩充 `SettingsSectionContributionDefinition`；
- 登记当前全部设置导航；
- 增加受信 renderer inventory；
- 导航、范围和内容按运行时贡献过滤；
- 本机网页控制台、自动化、项目资源和项目管理器设置即时撤下/恢复；
- 修正停用为 preview -> confirm -> execute。

### R7-3B：恢复 Surface

状态：已验收（2026-08-05）。

- 从 `MinimalSafeHome` 提供独立恢复入口；
- 抽取 Profile、模块、组件、依赖诊断和默认装配恢复；
- 在普通设置中心不可用时仍能打开；
- 完成后才允许 `builtin.settings-center` 被 Profile 停用。

### R7-3C：Schema 设置与组件包

状态：已验收（2026-08-05）。

- 定义版本化 settings schema；
- 提供路径选择、敏感值、校验、默认值和作用域存储；
- 安装后的组件可以只通过 manifest/schema 增加设置；
- 受信 renderer 继续只供内置宿主实现使用。

### R7-3D：所有权收敛

状态：已验收（2026-08-05）。

- 拆分会话、桌面集成和外部工具模块；
- 将常规和工具设置迁移给真实所有者；
- 设置中心仅保留宿主能力，不再直接拥有业务字段。

## 8. 验收

自动验收：

- TypeScript、Vite build、平台合同检查；
- Rust manifest 与前端贡献目录所有者一致；
- 每个受信 renderer ID 都有实现，每个实现都有目录定义；
- 动态撤下后没有失效导航 ID；
- `cargo check`、Rust 单元测试和 `git diff --check` 通过。

人工验收：

1. 停用本机网页控制台后，其工具和详细设置同时消失；
2. 停用自动化运行时后，全局脚本/插件和项目插件设置消失；
3. 停用项目资源后，全局排除与项目规则消失，项目范围在没有其他项目设置时隐藏；
4. 停用项目管理器后，历史与忽略列表消失；
5. 正在查看被撤下区域时不会白屏或闪到不存在的选项；
6. 重新启用模块后设置恢复，原值不丢失且不会自动执行任务；
7. 在停用确认框中取消，模块、贡献和后台资源完全不变化；
8. 桌面、窄窗口、浅色和深色主题下导航与正文不重叠。
9. 停用普通设置中心后，设置工具和普通设置窗口撤下，但主标签栏及最小安全主页仍可打开恢复设置；
10. 从恢复设置可查看 Profile、模块、组件和 Capability 诊断，并能恢复默认装配或退出程序；
11. 当前没有运行时组件声明 Schema 时显示明确空状态；平台合同 fixture 与 Rust 测试覆盖全局/项目存储、必填、类型、数值范围和默认值校验，项目值写入项目 `.pm_center`；
12. 停用会话运行时、桌面集成或外部工具后，只撤下各自拥有的设置；停用外部工具时 Blender 文件解析器入口与窗口同步撤下；
13. 恢复默认装配不会覆盖自定义 Profile，空白装配不依赖普通设置中心，取消任何停用确认均为零副作用。

以上 R7-3A/B/C/D 项目已于 2026-08-05 完成人工验收；主页保留的全局恢复设置属于 `core.recovery-settings`，不视为普通设置中心停用残留。
