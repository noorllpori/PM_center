# Nexora R15-R18 云端生态、宿主扩展与可视化装配路线

> 当前状态：R15、R16 为 `pending`；R17 Hosted Surface 与 R18 界面模板子路线为 `verifying`；完整 R17 ABI 与 R18 节点编排仍为 `pending`。
>
> 更新日期：2026-08-12
>
> 正式前置：R14 发布候选通过后，R15 才进入生产实现。
> 适用产品：闭源 Nexora 安装版 EXE 与其公开组件、Profile、装配空间合同

## 1. 编号冻结

本文件补齐此前没有写入项目书的 R15/R16，并固定 R15-R18 的含义：

| 里程碑 | 状态 | 固定名称 | 核心结果 |
| --- | --- | --- | --- |
| R15 | pending | 云端账户、组件商城与组件供应链 | 用户、发布者、组件源、已购/已安装、更新渠道、升级与版本回退。 |
| R16 | pending | 云设置、Profile/装配空间同步与团队库 | 多设备同步设置和装配，处理历史、冲突、恢复与团队分发。 |
| R17 | in progress | 公开宿主扩展 ABI 与可替换业务模块 | 界面模板 Hosted Surface 子路线正在验证；完整项目 Provider、菜单和业务模块 ABI 未完成。 |
| R18 | in progress | 可视化装配与受控节点编排 | 界面模板、类型化插槽和装配编辑正在验证；节点编排未开始。 |

R15 和 R16 是原有云端路线，不得被新的宿主扩展需求覆盖。R17 承接“第三方能否做出项目管理器级组件”，R18 承接此前保留的节点化与复杂界面装配方向。

本文件进入执行后，每个里程碑仍需拆成独立实施文档并按 `pending -> in-progress -> verifying -> accepted` 管理。未达到 `accepted` 的能力不能写进外部开发文档作为已开放接口。

## 2. 总体依赖

```text
R14 稳定发布基线
  -> R15 云账户、商城与组件供应链
  -> R16 云设置、Profile/装配空间同步
  -> R17 公开宿主扩展 ABI
  -> R18 可视化装配与受控节点编排
```

依赖理由：

- R15 复用 R9/R10 的组件运行时、签名、信任、依赖锁、原子安装和回退，不重建第二套包系统。
- R16 复用 R15 的账户、设备和云端 API，但组件二进制仍由 R15 组件源分发，设置同步不复制组件包。
- R17 发布长期兼容的宿主 ABI，必须建立在 R14 稳定基线和 R15 可控升级渠道上。
- R18 只组合 R11 自动化、R17 宿主贡献及现有 Profile 合同，不建立绕过生命周期和 Capability 的平行执行器。

R16 与 R17 的内部研究可以并行。当前已经实现的 R17/R18 界面模板子路线只用于验证受控 Surface 和插槽合同，不构成可对外承诺的完整宿主 ABI；完整 R17 仍需先满足发布与组件供应链前置。R18 节点编排必须等待 R17 的工作区、命令、数据和生命周期合同冻结。

## 3. R15：云端账户、组件商城与组件供应链

### 3.1 目标

让安装版 Nexora 用户能够登录、浏览组件、取得免费或已购组件、安装和更新，并能查看版本历史和回退。开发者通过安装版 Nexora 建立发布者身份、提交签名 `.pmc-pack`、管理版本和发布渠道，不需要 Nexora 源码仓库。

R15 负责组件供应链，不负责同步用户项目、聊天、媒体库或渲染成果。

### 3.2 固定范围

- 用户账户、设备会话、退出全部设备和凭据撤销；
- 发布者资料、发布密钥登记、密钥轮换和发布者状态；
- 官方源、团队源和用户添加的受信组件源；
- 商城目录、分类、搜索、版本说明、许可证、权限和依赖展示；
- 免费获取、购买凭证、已购组件库和退款/撤销后的可解释状态；
- 已安装、可更新、被 Profile 引用、被任务占用和可回退状态；
- `stable`、`beta`、`development` 更新渠道；
- 更新预览、依赖求解、Capability 变化、发布者变化和数据迁移提示；
- 原子升级、失败回滚、历史版本缓存和用户选择版本固定；
- 离线使用已安装组件，网络失败不破坏本地 Profile。

### 3.3 服务端和客户端边界

```text
Nexora EXE
  -> HTTPS API：账户、目录、授权、更新元数据
  -> 对象存储/CDN：签名 .pmc-pack
  -> 本地组件运行时：验签、依赖、安装、回滚、卸载
```

商城服务端可以决定“用户是否有权下载”，但不能替代包内发布者签名。客户端下载安装后仍执行 R10 的包头、BLAKE3、Ed25519、ZIP 路径、平台、ABI、依赖和 Capability 校验。

账户 access/refresh token 存入 Windows Credential Manager，不写入 Profile、装配空间、项目 `.pm_center` 或日志。支付信息不由 Nexora 客户端保存；客户端只保存服务端签名的最小授权摘要和离线有效期。

### 3.4 数据模型候选

- `CloudAccount`：用户、状态、区域和最近认证；
- `CloudDeviceSession`：设备 ID、名称、创建时间、最近活动和撤销状态；
- `PublisherIdentity`：发布者 ID、显示名、签名公钥和状态；
- `ComponentSource`：源地址、类型、信任、优先级和更新策略；
- `MarketplaceListing`：组件、分类、价格、许可证、权限摘要和支持渠道；
- `MarketplaceRelease`：版本、API 要求、平台、摘要、签名、依赖和变更说明；
- `ComponentEntitlement`：免费取得、购买、团队授权或开发者自有；
- `InstalledComponentState`：本机版本、来源、Profile 引用和可回退版本；
- `ComponentUpdatePlan`：下载、依赖、权限变化、迁移、阻塞和回滚步骤。

本地新增 `cloud-marketplace.db`，只保存缓存目录、账户非敏感摘要、组件源、授权缓存、下载记录、更新计划和回退索引。真实凭据继续放系统凭据库。

### 3.5 实施顺序

1. **R15-0 云合同与隔离测试服务**：冻结账户、目录、源、版本、授权和下载接口；提供本机测试服务，不连接真实支付。
2. **R15-1 账户与设备**：登录、刷新、退出、设备列表、撤销和离线状态。
3. **R15-2 组件源与商城目录**：多源目录、搜索、详情、签名元数据、渠道和缓存。
4. **R15-3 安装、更新与回退**：下载 staging、更新预览、依赖求解、原子安装、版本固定和回退。
5. **R15-4 已购与发布者工作流**：免费/购买授权、开发者发布、版本审核、下架和密钥轮换。
6. **R15-5 生产准备**：限流、审计、CDN、灾难恢复、隐私和真实安装版验收。

### 3.6 不包含

- 不把商城账户作为启动 Nexora 或运行本地组件的强制条件；
- 不允许服务端静默执行组件、切换 Profile 或修改项目；
- 不上传项目、聊天、渲染输出或媒体目录；
- 不把“已购买”误当成“已获得所有 Capability”；
- 不用包加密替代发布者签名和本机权限审批；
- 不在 R15 开放第三方 React、宿主 DOM 或内部 Tauri command。

### 3.7 验收

- 账户登录、刷新、退出、撤销设备和离线恢复行为确定；
- 未登录仍可使用本地功能和已安装组件；
- 多组件源同 ID/版本冲突有稳定选择规则；
- 损坏包、摘要不符、签名不符、来源替换和降级攻击被拒绝；
- 更新前显示依赖、权限、数据迁移和受影响 Profile；
- 安装或迁移任一步失败时恢复旧版本；
- 运行中组件、非幂等自动化和未保存页面会阻止不安全更新；
- 已购/免费/团队授权、下架和离线授权状态可解释；
- 干净 MSI 用户可以只通过 Nexora EXE 完成获取、安装、更新和回退。

## 4. R16：云设置、Profile/装配空间同步与团队库

### 4.1 目标

在用户明确开启后，同步软件级偏好、Profile 和装配空间，使同一账户的多台设备可以恢复工作方式；团队可以共享受控装配方案和组件版本清单。同步不是项目同步，也不是远程控制。

### 4.2 同步范围

允许同步：

- 常规外观、主题、语言、关闭确认等非敏感软件偏好；
- 功能中心 Pin、排序、导航和主页选择；
- 用户 Profile、模块/组件选择、布局、设置 schema 值和自动化绑定；
- `.pmc-workspace` 的可移植结构、普通变量和组件锁；
- 用户选择同步的开发者偏好，不包含私钥和开发目录信任；
- 团队装配库中的 Profile/Workspace 版本和发布说明。

永不自动同步：

- 密码、token、私钥、发布密钥和 Windows Credential Manager 内容；
- Blender、FFmpeg、Python、工具或用户目录的本机绝对路径；
- 项目文件、`.pm_center` 业务数据库、媒体文件和渲染结果；
- 聊天、联系人、接收文件、缓存、日志和任务运行输入输出；
- 组件开发目录信任和 Capability 长期授权。

组件包本体由 R15 组件源提供。R16 同步 Profile 后只生成“缺失组件与版本计划”，必须由用户确认后再通过 R15 安装。

### 4.3 冲突与历史

同步单元使用稳定 ID、revision、父 revision、内容摘要和设备 ID。上传使用乐观并发，不能以“最后写入时间”静默覆盖不同设备的修改。

冲突处理：

- 不同字段可安全合并时生成新 revision；
- 同一布局、绑定或设置被两台设备修改时保留两个版本并要求选择；
- 删除使用 tombstone，避免离线设备把已删除内容重新上传；
- 每个 Profile/Workspace 保留版本历史，可比较、恢复和复制为新方案；
- 应用云端版本仍经过本地 Profile 切换预览和事务回滚。

### 4.4 实施顺序

1. **R16-0 同步合同与隐私清单**：为每类字段标记 `syncable/local-only/secret/business-data`。
2. **R16-1 设备与同步状态**：设备名称、最近同步、暂停、退出和远端撤销。
3. **R16-2 软件偏好同步**：小范围、可恢复、无项目依赖的设置先上线。
4. **R16-3 Profile/Workspace 同步**：revision、冲突、历史、缺失组件计划和本机映射。
5. **R16-4 团队装配库**：所有者、编辑者、只读者、版本发布和撤销共享。
6. **R16-5 恢复与跨设备验收**：离线编辑、重装、损坏远端数据、账户退出和服务不可用。

### 4.5 验收

- 两台设备修改不同设置可以合并，修改同一字段不会静默覆盖；
- 同步 Profile 不上传绝对路径、密钥、聊天、项目或业务数据库；
- 缺失组件只产生安装计划，不自动购买、安装、授权或启动；
- 云端方案应用失败时继续保留当前本地方案；
- 退出账户后本地数据继续存在，并停止新同步；
- 删除、恢复历史、复制冲突版本和团队撤销权限行为一致；
- 服务端不可用时 Nexora 保持完整离线功能。

## 5. R17：公开宿主扩展 ABI 与可替换业务模块

### 5.1 目标

让外部组件在不访问 Nexora 源码、内部 React、Store、Tauri command 和 SQLite 表的情况下，做出项目管理器、媒体管理器或其他完整业务模块级体验。

R17 开放的是版本化宿主合同，不是内部实现对象。TreeCache、watcher、项目数据库和 Shell 继续由宿主管理，组件通过只读快照、事件和受控命令使用它们。

### 5.2 公开能力

#### Hosted Surface v1

- 组件可贡献 Shell 页面、项目工作区页、对话框和 Widget；
- 可声明导航、主页候选、单例范围、会话恢复和窄窗口行为；
- UI 使用隔离 WebView/iframe 与版本化消息桥，不加载第三方 React 到宿主进程；
- 页面崩溃只撤下自身，并可回退到宿主错误页。

#### Project Context v1

- 获取当前项目 ID、根目录别名、当前选择和活动工作区；
- 分页读取文件树快照、文件元数据和受控内容；
- 订阅项目打开、关闭、选择和文件变化事件；
- 通过 Capability Gateway 执行复制、移动、重命名、删除和创建；
- 读写组件自己的全局/项目命名空间状态。

组件不能直接持有 TreeCache 数据库连接、watcher、项目 `data.db` 或 `.pm_center` 任意写权限。

#### Context Action v1

- 声明文件、目录、集合、项目和工作区右键命令；
- 声明适用条件、优先级、批量选择、Capability 和执行语义；
- Profile 可启停、排序或覆盖默认绑定；
- 冲突、缺依赖、权限拒绝和组件卸载后有稳定回退。

#### Project Provider v1

- 组件可声明 `project-provider` 或 `project-manager` 角色；
- 一个 Profile 对同一独占角色只能选择一个有效提供者；
- 提供者拥有主页候选、项目打开入口、项目页和相关动作；
- Nexora 保留不可卸载恢复入口，提供者失效时回退安全 Shell；
- 停用/卸载必须先关闭页面、取消操作、释放订阅，再撤下贡献。

### 5.3 实施顺序

1. **R17-0 ABI v1 与兼容矩阵**：冻结消息、生命周期、错误、版本协商和资源上限。
2. **R17-1 Hosted Surface**：工作区、主页、导航、单例、会话恢复和崩溃隔离。
3. **R17-2 Project Context SDK**：项目快照、选择、事件、受控文件操作和组件状态。
4. **R17-3 Context Action/Widget/DataSource**：菜单、工具、结构化 Widget 和数据订阅。
5. **R17-4 可替换项目提供者**：独占角色、切换预览、停用、卸载和安全回退。
6. **R17-5 外部样板组件**：仅用安装版 Nexora 制作一个独立项目管理器样板并完成打包、商城安装、升级和回退。

### 5.4 验收

- 外部组件不修改 Nexora 源码即可提供主页、导航和项目工作区；
- 项目关闭或组件停用后没有残留页面、订阅、watcher、进程或数据库句柄；
- 多组件菜单和主页冲突可预览并稳定解决；
- 组件不能访问未授权项目、宿主 DOM、Tauri API 或内部数据库；
- Project Provider 更新/崩溃时不丢项目数据，并可恢复内置提供者；
- 使用 R15 商城安装和回退外部样板组件后 Profile 引用保持一致。

## 6. R18：可视化装配与受控节点编排

### 6.1 目标

让用户通过可视化编辑器组合页面、插槽、导航、Widget、数据源、命令和自动化。R18 不恢复旧 `WorkflowManifest` 的未完成执行器；它建立新的版本化编排合同，并复用 R11 和 R17 的真实能力。

### 6.2 两类编辑器

#### 界面装配图

- 选择 Shell/Page Template 和受控 `base.html`；
- 将 Surface、Widget、导航、工具和状态源放入命名插槽；
- 配置宽/窄窗口、可见条件、主题参数和空状态；
- 输出仍是普通 Profile/Workspace 数据，不生成隐藏的宿主代码；
- 预览失败不替换当前 Shell。

#### 自动化编排图 v2

- 节点来自组件声明的自动化命令、事件、条件、映射和审批节点；
- 端口由 JSON Schema 定义，连接前完成类型校验；
- 执行复用 R11 的 runId、operationId、幂等、取消、权限、日志和 attention；
- 禁止任意 Python、Shell、Tauri command 和未声明组件调用；
- 循环、并发、重试和副作用必须显式声明。

### 6.3 实施顺序

1. **R18-0 编排合同 v2**：与冻结的旧 Workflow 合同使用不同版本和命名，避免兼容误判。
2. **R18-1 界面装配画布**：模板插槽、页面、导航、Widget 和响应式预览。
3. **R18-2 自动化节点目录**：R11 命令/事件映射为类型化节点。
4. **R18-3 执行计划编译**：图编译为可审查的自动化绑定与执行计划。
5. **R18-4 调试与恢复**：逐步运行、日志、断点、取消、attention 和版本快照。
6. **R18-5 导出与商城模板**：装配图随 `.pmc-workspace` 交付，节点包通过 R15 分发。

### 6.4 验收

- 不写代码即可制作明显不同的主页、导航和工作区布局；
- 画布输出可导出、导入、版本比较和回退；
- 缺失组件、节点版本变化和类型不匹配会在保存/应用前阻止；
- 自动化图不会绕过 R11 的权限、幂等和 attention 语义；
- 任一页面或节点组件停用后，装配诊断指出准确引用，不进入半失效界面；
- 复杂方案在重启、离线、更新和跨设备同步后保持确定结果。

## 7. 跨里程碑公共原则

### 7.1 闭源与外部开发

- 第三方只依赖安装版 Nexora、公开文档、SDK 和开发者工作台；
- Nexora 源码、内部构建脚本和内部 CLI 不是扩展开发条件；
- Native EXE/DLL 可使用开发者自己的编译器，但校验、签名、安装和分发通过 Nexora；
- 任何能从内部实现观察到、但没有进入公开版本合同的接口都不是 API。

### 7.2 数据安全

- 停用、卸载、退出账户和取消同步默认不删除用户业务数据；
- 云端同步采用明确白名单，未知字段默认不上传；
- 包、Profile、Workspace 和同步 revision 都有摘要、版本和来源；
- 服务端、组件或页面失败不能让 Nexora 失去恢复入口；
- 所有高风险操作继续经过 Capability Gateway、生命周期和审计。

### 7.3 兼容和回退

- R15 组件升级必须保留原始已验证包或可重新取得的精确版本；
- R16 云端修订不能覆盖本机唯一副本，应用前创建恢复点；
- R17 ABI 使用主版本协商，未知必需能力阻止加载；
- R18 图保存不可变组件锁和输入 Schema 摘要，旧运行不自动使用新代码恢复。

## 8. 总体验收门槛

R15-R18 每个里程碑除专项验收外，都必须完成：

- TypeScript、Vite、Rust 单元/集成测试和 `cargo check`；
- 包、路径、权限、签名、身份、冲突和回滚安全测试；
- 干净 MSI、普通用户、离线、弱网和服务端不可用测试；
- 宽/窄窗口、浅色/深色、无项目/有项目检查；
- 停用、卸载、切换 Profile、应用退出和崩溃恢复；
- 资源泄漏检查，包括进程、端口、订阅、WebView、watcher 和 SQLite；
- 发布说明、数据位置、隐私说明、已知限制和回滚步骤。

## 9. 当前下一步

R15 和 R16 均为 `pending`，尚无安装版可用实现。R17/R18 只有界面模板与插槽装配子路线处于 `verifying`；不得把它表述为完整 Project Provider ABI、可替换项目管理器或节点画布。

当前先完成 R17/R18 子路线的人机验收和 R12-R14 的实机发布门槛。R14 达到发布门槛后，先创建 R15-0 云合同与隔离测试服务，冻结账户、组件源、授权与更新事务，再开始生产代码。
