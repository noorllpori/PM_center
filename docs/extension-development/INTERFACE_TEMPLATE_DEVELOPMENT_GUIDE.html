NEXORA EXTENSION DEVELOPMENT

界面模板与插槽装配开发指南

从一个空目录开始，制作可安装、可重载、可装配、可签名分发的 Nexora 主窗口布局。模板负责位置，组件 Surface 负责功能，装配方案负责绑定。

stable-2.8.5 核心合同 闭源安装版开发 data-pack 最后整理：2026-08-11

1. 模型与边界

界面模板

静态 HTML/CSS、响应式布局和类型化插槽。不运行代码。

组件 Surface

真正的交互页面。在隔离环境中运行，并通过组件命令访问能力。

装配方案

选择模板和组件，把页面、导航、标签或当前活动页面绑定到插槽。

宿主工具带不会被模板替换快捷栏、DEV、维护中心和 工具 Alt+Q 由 Nexora 固定保留。模板只控制它下面的区域。

模板不是一个完整网页。完全空白模板在没有绑定时可以保持空白；左右模板可以让左边固定显示音乐播放器，右边显示当前项目或启动主页。模板不读取文件、不调用 BlenderIO，也不拥有项目上下文。

能力状态当前行为

3. 最快开发流程

  1. 打开“编辑装配方案 -> 界面装配”，选择一个已有模板。
  2. 点击“复制为开发模板”，选择普通工作目录作为父目录。
  3. Nexora 会生成新组件 ID、信任开发目录并安装开发副本。
  4. 点击“VS Code”，修改 template.json、base.html 和 styles.css。
  5. 保存文件后回 Nexora 点击模板旁“重载”，或点击顶部 DEV。
  6. 插槽或主页绑定改变后，再点击“保存并应用”。
两种保存不要混淆VS Code 保存的是模板源文件；“保存并应用”保存的是装配方案草稿。修改 HTML/CSS 后需要重载，不需要靠“保存并应用”写模板。

4. 目录结构

my-interface-template/
  component.json
  README.md
  presentation/
    shell/
      my-shell/
        template.json
        base.html
        styles.css

安装时必须选择直接包含 component.json 的根目录，不要选择 presentation 或更深的子目录。目录名可改，公开 ID 不应随意改变。

5. component.json

{
  "schemaVersion": 1,
  "id": "com.example.interface-template",
  "name": "示例界面模板",
  "description": "提供一个可装配的双区域界面。",
  "version": "1.0.0",
  "apiVersion": "1",
  "runtime": "data-pack",
  "role": "data",
  "category": "appearance",
  "tags": ["interface-template", "layout"],
  "distribution": "local",
  "uiMode": "none",
  "platforms": ["any"],
  "entry": "presentation",
  "capabilities": [],
  "contributes": {
    "shellTemplates": [{
      "id": "com.example.shell.two-column",
      "name": "双区域布局",
      "version": "1.0.0",
      "templatePath": "presentation/shell/two-column/template.json"
    }]
  }
}
  • 外部表现模板必须使用 data-pack。
  • capabilities 必须为空。
  • 贡献 ID/版本必须与 template.json 完全一致。
  • entry 和 templatePath 都是包内安全相对路径。

6. template.json

{
  "schemaVersion": 1,
  "id": "com.example.shell.two-column",
  "kind": "shell",
  "version": "1.0.0",
  "semanticVersion": "1.0.0",
  "baseHtml": "presentation/shell/two-column/base.html",
  "styles": "presentation/shell/two-column/styles.css",
  "slots": [
    {
      "id": "left",
      "name": "左侧区域",
      "accepts": ["component-surface"],
      "multiplicity": "one",
      "layout": "single",
      "required": false,
      "collapseWhenEmpty": false
    },
    {
      "id": "right",
      "name": "右侧区域",
      "accepts": ["active-surface", "component-surface"],
      "multiplicity": "one",
      "layout": "single",
      "required": false,
      "collapseWhenEmpty": false
    }
  ],
  "regions": ["left", "right"]
}
字段规则
id稳定模板 ID，与组件贡献一致
kind主窗口布局使用 shell
slots只要非空，至少一个插槽接受 active-surface
required必需插槽没有有效绑定时阻止应用；空白布局应设为 false
collapseWhenEmpty要保留空白区域时显式设为 false
minWidth/maxWidth正整数，最小值不能大于最大值；高度同理

7. 插槽类型

accepts显示内容注意
active-surface当前项目、启动主页或当前 Shell 页面主内容通常绑定一次
component-surface指定组件的隔离页面受组件有效闭包和单例/多例规则约束
navigation当前方案导航由 Profile 条目决定内容
tabsShell 标签栏适合多页面工作区
toolbar当前项目工具栏无活动项目时为空
status当前项目状态无活动项目时为空
widgetWidget 内容完整第三方 Widget ABI 仍受 Hosted Surface 边界限制

multiplicity: one 必须搭配 layout: single。many 可使用 flow、stack 或 tabs。单例 Surface 不能在同一方案重复放置；多实例 Surface 必须由组件声明 instanceMode: multiple。

8. HTML 安全规则

<main class="split-template">
  <section class="split-template__pane split-template__pane--left">
    <nexora-slot name="left"></nexora-slot>
  </section>
  <section class="split-template__pane split-template__pane--right">
    <nexora-slot name="right"></nexora-slot>
  </section>
</main>

允许的结构标签

main header aside section footer div nav article
ul ol li p span h1 h2 h3 h4 h5 h6 hr figure figcaption

普通属性只保留 class、id、title、role、aria-*、data-* 和合法 tabindex。内联 style 会被丢弃。

明确禁止script、iframe、object、embed、link、内联事件、远程 URL、本机 URL、data:、动态 import、eval 和宿主对象。按钮、输入框、图片、音视频等交互或媒体应放进组件 Surface。

9. CSS 与响应式

.split-template {
  display: grid;
  grid-template-columns: minmax(0, 1fr) minmax(0, 1fr);
  min-height: 100%;
  height: 100%;
  min-width: 0;
  background: var(--nexora-surface, #ffffff);
}

.split-template__pane {
  display: flex;
  min-height: 0;
  min-width: 0;
  overflow: hidden;
}

@media (max-width: 720px) {
  .split-template {
    grid-template-columns: minmax(0, 1fr);
    grid-template-rows: minmax(0, 1fr) minmax(0, 1fr);
  }
}

Nexora 会自动把普通 CSS 规则限定在当前模板容器下。禁止 @import、表达式、脚本协议、文件协议和远程 URL。

  • Grid/Flex 根和子项都设置 min-width: 0。
  • 纵向可压缩区域设置 min-height: 0。
  • 所有 Nexora 颜色变量提供回退值。
  • 模板只控制布局，不强制组件页面字体和内部排版。
  • 当前宿主会给 component-surface 添加边框、背景和圆角，模板不要依赖移除它。

10. 方案绑定

{
  "shellLayout": {
    "hostToolbar": { "mode": "fixed" },
    "shellTemplate": {
      "id": "com.example.shell.two-column",
      "versionRequirement": "^1.0.0"
    },
    "interfaceTemplateStates": [{
      "templateId": "com.example.shell.two-column",
      "slotBindings": [
        {
          "id": "slot-left-player",
          "slotId": "left",
          "kind": "component-surface",
          "componentId": "com.example.music-player",
          "surfaceId": "com.example.music-player.surface",
          "enabled": true,
          "order": 10
        },
        {
          "id": "slot-right-active",
          "slotId": "right",
          "kind": "active-surface",
          "enabled": true,
          "order": 10
        }
      ]
    }]
  }
}

这段结构由装配编辑器生成，不要求用户手写。模板文件决定插槽，Profile 决定插槽内容。每个模板按 templateId 保存独立状态，切换模板不会删除原绑定。

重命名插槽是公开合同变更。旧 Profile 中的 slotId 可能失效，应提升版本并提供迁移说明。

11. VS Code 与安全重载

  1. 只编辑“复制为开发模板”生成的受信任开发目录。
  2. 保存文件后点击模板旁“重载”，或顶部 DEV。
  3. 重载会重新校验 Manifest、HTML、CSS、插槽和路径。
  4. 校验或安装失败时保留旧运行版本，避免主界面进入半失效状态。
  5. 模板源码重载后，Profile 绑定仍是原草稿；只有方案改变才“保存并应用”。
当前不是自动热更新Watcher 只标记开发目录发生变化，不自动执行新代码。显式重载是安全边界，也是出现错误时可以回滚的原因。

12. 左右 50% 完整样例

正式样例位于 examples/split-interface-template，与最小空白模板分开。它声明两个可选且不折叠的插槽：

left

接受一个 component-surface，适合固定音乐播放器或工具面板。

right

接受 active-surface 或 component-surface，适合主页/项目工作区。

窄窗口

宽度低于 720px 时变成上下各 50%，避免横向挤压。

  1. 从目录安装样例根目录。
  2. 在当前 Profile 启用“左右对半界面模板”。
  3. 在安装的界面模板中选择“左右对半布局”。
  4. 左侧选择 Ninniku 音乐播放器，右侧加入“主页 / 当前活动页面”。
  5. 选择启动主页并“保存并应用”。

13. 打包、分发与版本

  1. 在开发者工作台校验并信任模板开发目录。
  2. 创建保存在组件目录之外的 Ed25519 私钥。
  3. 填写发布者和许可证，生成签名 .pmc-pack。
  4. 在干净 Nexora 环境测试安装、启用、切换、卸载和重装。
  5. 需要交付整套装配时，再导出 .pmc-profile 或自包含 .pmc-workspace。
修改版本建议理由
CSS 调整，不改插槽Patch不改变绑定合同
增加可选插槽Minor旧 Profile 仍可使用
改变 accepts/multiplicityMinor 或 Major旧绑定可能不兼容
删除/重命名插槽Major旧 slotId 会失效
改变模板 ID新模板旧状态不会自动继承

14. 故障排查

现象常见原因处理
安装一直转圈选错目录、清单无效、运行占用选择含 component.json 的根目录，先在工作台校验并看日志
修改后没变化改了安装副本或尚未重载编辑受信任开发目录，保存后点“重载”
不能保存方案模板/依赖/插槽/版本诊断查看底部阻止原因，优先处理缺失模板和旧 slotId
“+ 主页”没反应one 插槽已占用或已有同类绑定移除现有绑定，确认旧状态已迁移
提示必须有主插槽没有 accepts: active-surface至少给一个插槽加入 active-surface
空区域消失collapseWhenEmpty 默认为 true显式设为 false
组件页面不在列表组件未启用、依赖无效或 placements 不允许检查当前方案闭包、版本和 scriptSurfaces
图片/按钮不显示模板宿主只允许静态结构标签把交互和媒体放进 Script Surface
版本不满足 ^1.0.0Profile 要求与安装版本不兼容安装匹配版本或更新方案要求

15. 发布验收

  • 组件贡献和 template.json 的 ID/版本完全一致。
  • 至少一个插槽接受 active-surface，空白语义不误用 required。
  • 普通、窄窗口、浅色、深色和缩放下无重叠或横向溢出。
  • 有项目、无项目、切换主页和关闭标签时 active-surface 正常。
  • 组件 Surface 缺失、停用或崩溃时模板可回退。
  • 开发重载失败保留旧运行版本，没有重复页面或残留绑定。
  • 切换模板再切回，原模板状态保持。
  • 签名包在干净环境可安装、卸载和重装。
  • Profile 缺包时显示依赖诊断，Workspace 自包含导入执行签名检查。
