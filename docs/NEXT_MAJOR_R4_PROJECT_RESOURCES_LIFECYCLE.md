## 1. 本次范围

本次是 R4 第三个独立验收领域，管理项目打开后长期存活的资源：

- `.pm_center/data.db` 项目元数据连接注册表；
- `.pm_center/tree_cache.db` 目录树与解析缓存连接注册表；
- 当前活动项目的递归 watcher 和事件消费线程；
- 每 2 秒、每次最多 25 个目录的脏目录修复任务；
- 项目缓存维护与关闭项目之间的取消、等待和索引失效处理；
- 目录缩略图后台任务在项目关闭后的写入守卫。

渲染数据库、Blender Worker、Python/插件进程和普通文件操作分别留在后续 R4 分项，不在本次迁移。

## 2. 项目租约

后端维护已打开项目注册表，每个项目记录规范化路径和排除规则。只有模块运行且项目仍有租约时，才能新建项目数据库、TreeCache、watcher 或缩略图写入任务。

关闭外层项目标签时先撤销租约，再依次释放资源。这样已经排队但尚未执行的异步目录读取无法在清理完成后重新打开 SQLite。

稳定错误前缀：

```text
PROJECT_RESOURCES_MODULE_DISABLED
PROJECT_RESOURCES_PROJECT_NOT_OPEN
```

模块启动恢复期间使用 `PROJECT_RESOURCES_MODULE_STARTING`，项目初始化会等待模块恢复完成，避免会话恢复与后台模块异步启动之间的竞争。

## 3. 生命周期所有权

`builtin.project-resources` 为项目作用域内置模块，由一个全局协调器管理多个已打开项目：

- `Database` 聚合资源拥有项目数据库注册表、TreeCache 注册表和 watcher；
- `TokioTask` 资源拥有脏目录修复循环；
- watcher 仍只监听当前活动项目，不轮询休眠项目；
- 非活动但仍打开的项目保留数据库和 TreeCache 连接，关闭对应项目标签后立即释放。

### 启用

1. 开放项目租约和项目命令；
2. 登记聚合清理资源；
3. 启动脏目录修复任务；
4. 恢复仍然打开的项目数据库和 TreeCache；
5. 恢复之前的活动项目 watcher。

### 停用

1. 关闭项目访问守卫，拒绝新句柄和新缩略图写入；
2. 取消全部缓存维护任务；
3. 停止脏目录修复任务；
4. 停止 watcher 并等待事件线程写完最后一批事件；
5. 将现有目录索引标记为脏；
6. 释放全部 `data.db` 和 TreeCache 连接；
7. 保留项目注册信息，重新启用后恢复当前已打开项目。

## 4. 单项目关闭

关闭一个项目不会影响其他已打开项目：

1. 从注册表撤销该项目租约；
2. 如果它是活动项目，停止 watcher；
3. 取消并等待该项目缓存维护；
4. 标记根目录索引为脏；
5. 删除进程内 `data.db` 与 TreeCache 句柄；
6. 保留 `.pm_center` 全部文件、脚本、插件、缩略图和用户数据。

项目重新打开后建立新连接并复用原数据。切换项目只切换 watcher，不关闭其他仍有标签的项目资源。

## 5. 健康检查

模块健康信息显示：

- 已注册项目数；
- `data.db` 连接数；
- TreeCache 连接数；
- watcher 与事件线程是否同时运行；
- 当前缓存维护任务数。

注册项目数与数据库/缓存数不一致，或活动项目 watcher 缺失时进入 `degraded`，不自动删除或重建项目数据。

## 7. 人工验收

- [ ] 同时打开两个项目，切换时只有当前项目 watcher 活跃；
- [ ] 关闭非活动项目，不影响当前项目浏览和 watcher；
- [ ] 关闭活动项目后，其 `data.db`、`tree_cache.db`、WAL 和 SHM 可以移动或重命名；
- [ ] 重新打开项目，标签、集合、备注和目录缓存仍存在；
- [ ] 停用“项目资源”后，项目浏览与缓存命令收到模块停用提示；
- [ ] 重新启用后当前打开项目恢复，无需重新创建 `.pm_center`；
- [ ] 缓存深度检查或重建过程中停用模块，任务可取消且项目数据不损坏；
- [ ] 连续打开、切换和关闭项目后，模块资源计数不会持续增长。

## 8. 数据安全

- 停用和关闭项目都不删除 `.pm_center` 文件；
- `data.db`、脚本和插件始终属于受保护数据；
- 缓存维护被中断时旧目录索引保留，并标记为脏供重新打开后修复；
- 项目路径不存在时只报告错误，不创建替代目录；
- 本次不迁移数据库结构，不改变项目格式，也不升级应用版本。
