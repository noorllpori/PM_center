# 下一项计划：百度网盘跨设备同步

状态：规划中

## 目标

在现有 PMC Server 跨网络协作之外，增加一个可选的百度网盘同步通道。用户在项目中开启同步后，多个设备通过同一个百度网盘同步目录交换文件；PMC Server 负责保存项目清单、文件 hash、版本和同步状态，不保存文件正文。

第一版默认按“每台设备分别登录同一个百度账号”设计。百度授权状态只保存在各设备本地的 `baidu-drive` skill 配置中，绝不上传到 PMC Server，也不写入项目仓库。

## 核心架构

```text
设备 A 本地项目  --上传/下载-->  百度网盘 /apps/bdpan/PMC同步目录/<sync-id>/  <--上传/下载--  设备 B 本地项目
       |                                      ^                                      |
       +------------ 清单、hash、版本、差异、冲突 ------------> PMC Server <-----------+
```

- PMC Server 是控制面：设备登记、清单交换、差异计算、版本提交、冲突记录和任务状态。
- 百度网盘是数据面：文件实际上传、保存和下载由每台设备本地的 `baidu-drive` skill 完成。
- PMC Server 不中转文件字节，不落盘保存文件内容，不保存 AppKey、SecretKey、access token 或百度账号密码。
- 百度远端路径固定在 `/apps/bdpan/` 范围内，项目同步根目录使用 `PMC同步目录/<sync-id>/`，不能访问个人网盘根目录。

## 同步清单

每个同步项目绑定一个 `sync_id` 和一个本地项目根目录。客户端只向服务器发送相对路径，不发送本机绝对路径。

每项清单至少包含：

- `relative_path`：使用 `/` 的 UTF-8 相对路径，拒绝绝对路径、`..`、空段和 Windows 保留名。
- `kind`：文件或目录。
- `size`：文件字节数。
- `blake3`：文件内容 BLAKE3 hash，作为跨设备判断内容是否一致的主要依据。
- `remote_path`：百度网盘中的相对路径；不保存 access token。
- `version`、`updated_by`、`updated_at`：同步版本和来源设备。
- `deleted`：删除使用墓碑记录，第一版不直接从服务器清除历史状态。

默认排除 `.pm_center`、临时文件、同步暂存目录和调用方配置的排除规则，避免把 PMC 运行数据库、半成品或凭据文件同步到云端。

## 同步流程

1. 用户在项目设置中开启百度网盘同步，PMC 检查本机 skill 是否已安装、已登录，以及同步目录是否可访问。
2. 客户端扫描项目并计算本地清单。计算过程进入任务面板，支持进度、取消和失败重试。
3. 客户端通过 PMC Server WebSocket 分块提交清单。服务器只保存清单摘要和条目，不接收文件正文。
4. 服务器以“上次已确认版本”为基线计算上传、下载、删除和冲突项，先返回差异预览。
5. 用户确认同步策略后，客户端分别调用本地 `scripts/baidu-pan.mjs` 桥接器执行百度上传或下载。
6. 上传后客户端重新检查本地 hash；下载先写临时文件，BLAKE3 校验通过后再原子替换目标文件。
7. 百度操作和本地校验都完成后，客户端向服务器提交操作结果，服务器生成新的清单版本。
8. 文件删除先进入墓碑和待确认状态。默认只删除本地或标记云端差异，不自动删除另一端内容。

## 差异和冲突规则

以服务器保存的上次同步 hash 作为共同基线：

| 本地相对基线 | 云端相对基线 | 处理 |
| --- | --- | --- |
| 未变化 | 已变化 | 下载云端版本 |
| 已变化 | 未变化 | 上传本地版本 |
| 未变化 | 未变化 | 跳过 |
| 已变化 | 已变化且 hash 不同 | 标记冲突，不能自动覆盖 |
| 一端删除，另一端未变化 | - | 进入删除确认 |
| 同一内容 hash 相同但路径不同 | - | 可标记为移动候选，第一版不自动改名 |

冲突中心需要展示本地版本、云端版本、大小、hash、修改时间和来源设备。默认提供“保留本地”“保留云端”“两份都保留”“跳过”四种选择，二进制文件和 Blender 资源不做内容合并。

## 服务端数据和协议

计划在 PMC Server SQLite 中增加以下数据域：

- `sync_spaces`：同步项目、项目标识、远端目录、开关和同步策略。
- `sync_devices`：设备在线状态、客户端版本和最近一次清单时间，不保存百度授权信息。
- `sync_manifest_entries`：路径、kind、size、BLAKE3、远端路径、版本、墓碑和来源设备。
- `sync_operations`：扫描、上传、下载、删除确认、校验和提交状态，使用幂等操作 ID。
- `sync_conflicts`：双向修改、删除与修改、版本不一致等冲突记录。

WebSocket 消息需要支持清单开始/分块/结束、差异结果、操作确认、进度状态、冲突处理和版本提交。清单和路径都必须经过服务端大小、数量、路径穿越和版本校验，不能因为客户端伪造 hash 就覆盖其他设备的已确认版本。

## PMC 界面

第一阶段在项目设置增加：

- 百度网盘同步开关。
- 同步根目录选择和当前登录状态。
- 最近同步时间、当前版本、待上传/下载/冲突数量。
- “扫描差异”和“开始同步”按钮。

第二阶段增加同步中心：

- 按上传、下载、删除、冲突和失败分类查看。
- 单项或批量确认，支持取消和重试。
- 显示本地路径、云端路径、hash、大小和来源设备。
- 服务器离线、百度未登录、授权失效、空间不足和网络中断时给出可恢复提示。

## 分阶段实施

### 阶段 0：桥接能力验证

- 为 `baidu-pan` CLI 增加稳定的机器可读状态和错误分类。
- 验证 Windows 打包环境能调用 Node/WSL skill，确认登录失效、上传、下载、重名和目录操作行为。
- 明确 `bdpan ls --json` 可返回的远端大小、时间、路径和标识字段；不读取 skill 配置文件。

### 阶段 1：服务器清单和差异预览

- 增加同步数据表、协议版本和清单分块接口。
- 实现相对路径校验、BLAKE3 清单、基线版本和差异计算。
- 先只做“扫描差异”，不写入文件，完成单机和双机协议测试。

### 阶段 2：手动双向同步

- 接入百度上传/下载任务。
- 加入临时文件、hash 校验、原子提交、幂等重试和失败恢复。
- 完成上传、下载、删除确认和冲突中心。
- 默认不自动删除、不自动覆盖，所有批量写入先显示差异。

### 阶段 3：后台同步

- 接入项目 Watcher，使用防抖和队列合并连续变化。
- 增加手动、定时和“项目关闭前同步”等策略。
- 支持暂停、恢复、限速和系统托盘状态提示。
- 应用退出或服务器断开时保留可重试任务，不把部分文件标记为完成。

### 阶段 4：稳定性和扩展

- 大目录分块扫描、长文件传输、断网恢复和空间预检。
- 远端被百度客户端或其他工具改动时的漂移检测。
- 多项目同步、同步历史回滚和更细粒度的权限策略。
- 如果以后要支持不同百度账号，不直接共享 token，另行设计云端共享授权模型。

## 验收标准

- 两台设备可用同一同步项目完成首次上传和首次下载。
- 未变化文件不会重复上传或下载，hash 一致时任务可安全跳过。
- 单端修改只同步修改端，双端同时修改必然进入冲突中心。
- 中断、重启、服务器断线、百度授权失效和重名都能恢复或明确失败，不能留下伪完成文件。
- 服务端数据库和日志中没有文件正文、百度 token、本机绝对路径或账号密码。
- `.pm_center`、临时文件和排除规则不会被同步。
- 路径穿越、非法文件名、超大清单、重复操作 ID 和伪造版本请求均被拒绝。

## 第一版明确不做

- 不让 PMC Server 直接保存或中转文件内容。
- 不把百度授权状态集中到服务器。
- 不默认覆盖本地文件或删除云端文件。
- 不做文本、图片或 Blender 文件的内容级合并。
- 不把“已登录百度”误认为“已完成同步”；每次同步都必须有清单、操作和 hash 校验结果。
